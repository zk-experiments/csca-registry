# csca_registry (Noir)

In-circuit verification against the csca-registry commitment. Every circuit that needs "this CSCA key is registered, was valid on date D, and this DSC serial is not revoked" imports this library; nothing else computes registry leaves.

```toml
[dependencies]
csca_registry = { git = "https://github.com/zk-experiments/csca-registry", tag = "vX.Y.Z", directory = "noir/csca_registry" }
```

Use the same tag as the `csca-registry` release whose `registry.json` the prover reads: the leaf format (`LEAF_VERSION`) is part of the release.

## Specification

All hashing is `H(x₁…xₙ) = Poseidon2::hash([x₁…xₙ], n)` from `noir-lang/poseidon` v0.3.0 (BN254, t = 4, rate 3, iv = n·2⁶⁴, no trailing permutation when n is a multiple of 3). The Rust side (`src/commitment.rs::poseidon2`) implements the same sponge on `pso-poseidon`'s permutation.

| value | definition |
|---|---|
| `pack_be(b)` | 31-byte big-endian chunks, short chunk taken from the front, least significant chunk first |
| `key_hash` | `H(pack_be(key))`; key = RSA modulus (big-endian, no leading zeros) or EC `x ‖ y` (each padded to the field size) |
| `header_field` | the 29 bytes `version(2) ‖ type(1) ‖ country[3] ‖ key_type ‖ curve ‖ bits[2] ‖ exponent[4] ‖ open[8] ‖ close[8]` read as one big-endian integer |
| key leaf | `H(header_field, key_hash)`; one leaf per (key, validity period) |
| revocation leaf | `H(issuer_key_hash, H(serial))`; `serial` ≤ 20 bytes, so `pack_be` is one field equal to the serial as an integer |
| `merkle_root` | binary tree, `H(left, right)` per level, bit `l` of `index` selects the side; empty slots are 0 with `zero[l+1] = H(zero[l], zero[l])` |
| `state_root` | `H(LEAF_VERSION, keys_root, revocations_root)`; this is `commitment.root` in `registry.json` |

Heights: key tree 16, revocation tree 14. `country` is the ICAO three-letter code; `country_from_mrz` maps the MRZ issuing state to it (`D<<` → `DEU`).

## API and constraints

`verify_key::<N, M>(root, revocations_root, header, public_key, path, at) -> key_hash` asserts:
1. `header.open ≤ at ≤ header.close`;
2. `state_root(merkle_root(key_leaf(header, key_hash(public_key)), path), revocations_root) == root`.

`verify_not_revoked::<H>(revocations_root, issuer_key_hash, serial, witness)` asserts, with `t = revocation_leaf(issuer_key_hash, serial)`:
- the `upper` path reaches `revocations_root`;
- with a lower bound: the `lower` path reaches the root, `lower_leaf ≠ 0`, `lower_leaf < t`, `upper.index = lower.index + 1`, and `upper_leaf = 0` or `t < upper_leaf`;
- without one: `upper.index = 0`, and `upper_leaf = 0` (the tree is empty: a canonical tree has a zero slot 0 only when it has no leaves) or `t < upper_leaf`.

`merkle_root` constrains `index < 2^H` (`to_le_bits`). Field comparisons use `Field::lt` (full-width, constrained).

## Assumptions (for review)

- **Root authenticity is the caller's job.** `root` must be a public input checked against the root published on-chain for the registry release. This library only proves consistency with it.
- **Canonical revocation tree.** Exclusion soundness needs strictly ascending, non-zero leaves packed from slot 0 with zero padding. csca-registry builds trees that way and `csca-registry verify` re-checks a registry; a non-canonical tree could hide a revoked serial.
- **What `at` means is the caller's policy.** Pass the verification date for the shell model, or the DSC's `notBefore` for ICAO's chain model. The period is already cut at the key's revocation time.
- **The key bytes must be the key the circuit actually verifies with.** Callers must feed the same `public_key` bytes into signature verification; the leaf binds only those bytes (and `header`), not the certificate.
- **`country` binding is the caller's job.** Compare `header.country` with `country_from_mrz(dg1 issuing state)` so a CSCA of one state cannot vouch for another state's document.

## Tests

`src/vectors.nr` is generated by `tests/noir_vectors.rs` in the Rust crate from `tests/fixtures/sources` (a German brainpoolP512r1 key, an Italian RSA-4096 key, the Italian CRL). CI fails if it is stale. `nargo test` covers inclusion for both keys, date bounds, widened periods, another country, a tampered path, a substituted key, exclusion before, between and after the revoked leaves, exclusion from an empty tree (and a non-empty tree claiming to be empty), revoked serials, and MRZ normalisation.
